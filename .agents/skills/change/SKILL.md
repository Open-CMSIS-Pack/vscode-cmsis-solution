# Change

1. Read and follow the [development principles](../../references/development-principles.md).
2. Follow the repository [TypeScript requirements](../../../.github/instructions/typescript.instructions.md) when changing TypeScript or TSX files.
3. Assess test scope for testable changes:
   - Follow the [unit-tests skill](../unit-tests/SKILL.md) for isolated unit or component tests.
   - Follow the [e2e-tests skill](../e2e-tests/SKILL.md) for tests of user workflows across real system boundaries.
4. Follow the [git-mv skill](../git-mv/SKILL.md) when moving or renaming Git-tracked files or directories.
5. Follow the [structured-files skill](../structured-files/SKILL.md) when implementing JSON, YAML, or XML parsing, creation, or updates.
6. Follow the [copyright skill](../copyright/SKILL.md) for covered source files that are added or changed.
7. Consult the [architecture](../../references/architecture.md), [structure](../../references/structure.md), and [module map](../../references/modules.md) only as needed.
8. Follow the approved plan when one exists.
9. Make the smallest complete change that satisfies the request.
10. Run focused validation after editing.
