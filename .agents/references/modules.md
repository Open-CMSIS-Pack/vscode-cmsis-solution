# Modules

Module ownership and relationships.

Rows represent cohesive runtime subsystems, public contracts, user-interface
surfaces, or meaningful declarative and tooling boundaries. Dependencies name
immediate architectural relationships rather than every imported utility or
third-party package.

| Module | Primary path | Responsibility | Depends on |
| --- | --- | --- | --- |
| Extension composition root | [src/desktop/extension.ts](../../src/desktop/extension.ts) | Constructs implementations, injects dependencies, activates extension-host services, and returns the public extension API. | All extension-host runtime modules; VS Code API |
| Public extension API contract | [api/csolution.d.ts](../../api/csolution.d.ts), [api/csolution-api-v2.d.ts](../../api/csolution-api-v2.d.ts) | Publishes the versioned TypeScript contract for boards, devices, drafts, solution creation, and builds to other extensions. | VS Code API types |
| Extension API adapter | [src/api](../../src/api) | Adapts internal data, solution creation, and build services to the public extension API contract. | Public extension API contract; Hardware and draft data catalog; Solution creation and import; Build and generator tasks |
| CMSIS common package | [packages/cmsis-common](../../packages/cmsis-common) | Provides generic tree and file models, parsers, and serializers for text, JSON, YAML, and XML, plus schemas, lazy values, and utility types. | Node.js file system; YAML, JSON, and XML libraries |
| VS Code adapter layer | [src/vscode-api](../../src/vscode-api) | Wraps commands, configuration, files, workspace state, extension APIs, messages, output, decorations, processes, and terminals for testable use. | VS Code API; Node.js process facilities |
| Environment and tool acquisition | [src/desktop/env-manager.ts](../../src/desktop/env-manager.ts), [src/vcpkg](../../src/vcpkg) | Builds process environments, integrates Python environments, acquires default toolsets, and configures solution workspaces. | VS Code adapter layer; Environment Manager extension; Python Environments extension |
| csolution JSON-RPC client | [src/json-rpc/csolution-rpc-client.ts](../../src/json-rpc/csolution-rpc-client.ts) | Owns the persistent `csolution rpc` process, typed requests, serialization, lifecycle, locking, and pack-index reload watchers. | Environment and tool acquisition; VS Code adapter layer; CMSIS Toolbox |
| Solution model and lifecycle | [src/solutions/solution-manager.ts](../../src/solutions/solution-manager.ts), [src/solutions/csolution.ts](../../src/solutions/csolution.ts) | Loads and mutates solution, project, and build models; tracks the active solution; caches RPC data; and publishes lifecycle state. | CMSIS common package; csolution JSON-RPC client; Environment and tool acquisition; VS Code adapter layer |
| Solution workflow coordination | [src/solutions/solution-event-hub.ts](../../src/solutions/solution-event-hub.ts) | Coordinates conversion, build setup, generator completion, diagnostics, and state refresh across solution services. | Solution model and lifecycle; CMSIS Toolbox execution; csolution JSON-RPC client |
| Solution creation and import | [src/solutions/solution-creator.ts](../../src/solutions/solution-creator.ts), [src/solutions/mdk-conversion](../../src/solutions/mdk-conversion) | Creates solutions from templates or catalog drafts, imports MDK projects, and initializes workspaces, Git, and tool configuration. | Hardware and draft data catalog; Solution model and lifecycle; Declarative formats and assets; Environment and tool acquisition; VS Code adapter layer |
| CMSIS Toolbox execution | [src/solutions/cmsis-toolbox.ts](../../src/solutions/cmsis-toolbox.ts) | Serializes `cbuild`, `csolution`, and `cpackget` operations and manages execution, cancellation, version checks, setup messages, and RPC suspension. | csolution JSON-RPC client; VS Code adapter layer; CMSIS common package; CMSIS Toolbox |
| Hardware and draft data catalog | [src/data-manager/data-manager.ts](../../src/data-manager/data-manager.ts) | Provides a source-neutral facade that aggregates boards, devices, packs, and draft projects while preserving source-specific lazy details. | Solar Search client; csolution JSON-RPC client; CMSIS common package |
| Solar Search client | [src/solar-search/solar-search-client.ts](../../src/solar-search/solar-search-client.ts) | Implements GraphQL discovery of remote boards, devices, packs, and example projects. | Solar Search service; generated GraphQL client |
| Build and generator tasks | [src/tasks](../../src/tasks) | Defines VS Code tasks and commands, derives build arguments, runs builds and generators, and handles cancellation. | Solution model and lifecycle; CMSIS Toolbox execution; VS Code adapter layer |
| Debug configuration | [src/debug/debug-launch-provider.ts](../../src/debug/debug-launch-provider.ts), [src/eta-ext](../../src/eta-ext) | Reads topology and adapter data, renders debug templates, and maintains generated launch and task configurations. | Solution model and lifecycle; CMSIS common package; VS Code adapter layer; Declarative formats and assets |
| IntelliSense and language integration | [src/solutions/intellisense](../../src/solutions/intellisense), [src/solutions/language-features](../../src/solutions/language-features), [src/solutions/clangd-manager.ts](../../src/solutions/clangd-manager.ts) | Generates and parses compile commands, configures clangd contexts, obtains compiler defines, and provides solution-aware language features. | Solution model and lifecycle; Build and generator tasks; VS Code adapter layer; clangd contexts extension |
| Shared webview infrastructure | [src/views/webview-manager.ts](../../src/views/webview-manager.ts), [src/views/message-handler.ts](../../src/views/message-handler.ts), [src/views/common](../../src/views/common) | Manages webview panels, content security policy, resources, typed request messaging, and shared React user-interface infrastructure. | VS Code API; React; webview messaging libraries |
| Feature webviews | [src/views](../../src/views) | Supplies extension-host controllers and five browser bundles for solution creation, solution management, components and packs, layers, and configuration. | Shared webview infrastructure; Solution model and lifecycle; Solution workflow coordination; Hardware and draft data catalog; csolution JSON-RPC client; Debug configuration |
| Solution Outline view | [src/views/solution-outline](../../src/views/solution-outline) | Presents the active solution as a native VS Code tree and owns its edit, open, find, merge, source, and decoration commands. | Solution model and lifecycle; VS Code adapter layer; Build and generator tasks |
| Declarative formats and assets | [schemas/README.md](../../schemas/README.md), [templates](../../templates) | Owns workspace schemas and seed content for solutions, projects, Git setup, and debug configurations. | Consumed by Solution creation and import, Environment and tool acquisition, and Debug configuration |
| External runtime tools | [tools](../../tools) | Contains platform-specific external executables and native packages used while the extension runs, including CMSIS Toolbox, `uv2csolution`, and `node-pty`. These artifacts are not maintained in this repository and are downloaded by internal preparation scripts as build prerequisites. | Repository build and packaging tooling; external release and package artifacts |
| Unit test support | [src/__test__](../../src/__test__) | Contains reusable code exclusively for unit tests, including factories, custom matchers, waits, DOM events, mock workspace setup, and temporary test-data management. | Jest; VS Code mocks; Prepared unit test data |
| Prepared unit test data | [test-data](../../test-data) | Contains specially prepared files, documentation, paths, and CMSIS solution trees used as deterministic input and expected data by unit tests. | Consumed by Unit test support and unit tests across runtime modules |
| Repository build and packaging tooling | [scripts](../../scripts), [webpack.config.js](../../webpack.config.js) | Downloads external artifacts, generates interfaces and clients, builds host and browser bundles, packages VSIX files, and maintains licenses and repository checks. | npm workspaces; webpack; artifact services; VS Code Extension tooling |

Generated clients and interfaces, individual test files, coverage, media, and
individual schema or template files belong to their owning modules and are not
separate modules in this map.
